# Crawler Target Expansion Plan

MoonCen의 장기 목표는 마트/백화점 문화센터를 넘어 강의, 강좌, 체험, 원데이 클래스 정보를 폭넓게 수집하는 것이다. 이 문서는 수집 대상을 체계적으로 발굴하고 우선순위를 매겨 크롤러로 확장하기 위한 기준 문서다.

## 목표

- 전국 단위 문화센터와 지역 강좌 정보를 한곳에서 검색할 수 있게 한다.
- 수집 대상마다 난이도, 가치, 법적/운영 리스크를 기록한다.
- 크롤러 구현 전에 대상 목록을 먼저 표준화한다.
- 신규 크롤러 추가 후 품질 리포트로 지속 관리한다.

## 수집 대상 범위

| 우선순위 | 그룹 | 대상 예시 | 특징 |
|---:|---|---|---|
| 1 | 대형마트 | 홈플러스, 이마트, 롯데마트 | 전국 지점, 강좌 수 많음, 현재 핵심 데이터 |
| 1 | 백화점 | 롯데백화점, 현대백화점, 신세계아카데미, AK플라자, 갤러리아 | 수강료가 높지만 콘텐츠 품질 좋음, 지점 기반 검색에 적합 |
| 2 | 쇼핑/아울렛 | NC백화점, 뉴코아, 이랜드리테일, 스타필드/복합몰 | 지역별 강좌/체험성 프로그램 가능성 |
| 2 | 지자체 | 평생학습관, 여성회관, 주민자치센터 | 지역 밀착형, 사이트 구조가 기관마다 다름 |
| 2 | 도서관 | 공공도서관 문화강좌, 독서문화프로그램 | 무료/저가 강좌 많음, 아동/가족 프로그램 많음 |
| 3 | 육아/아동 | 육아종합지원센터, 공동육아 프로그램 | 영유아 대상 필터와 궁합 좋음 |
| 3 | 청소년 | 청소년수련관, 청소년문화의집 | 초중고 대상 프로그램 많음 |
| 3 | 공공/기관 | 한국마사회 문화센터, 체육문화센터, 국민체육센터 | 특정 지역 또는 지점 기반 강좌 |
| 4 | 민간 클래스 | 클래스101, 솜씨당, 프립, 원데이클래스 플랫폼 | 상품성 높지만 약관/로그인/API 정책 확인 필요 |

## 우선순위 기준

| 기준 | 점수 관점 |
|---|---|
| 데이터 가치 | 강좌 수, 지점 수, 사용자 수요, 아동/가족 강좌 비중 |
| 수집 안정성 | HTML 구조 안정성, 공개 API 존재, 페이지네이션 명확성 |
| 접근성 | 로그인 불필요, 캡차 없음, 검색 결과 공개 |
| 위치 품질 | 지점 주소/좌표 확보 가능 여부 |
| 필드 완성도 | 제목, 지점, 일정, 기간, 수강료, 대상, 이미지, 상세 설명 |
| 운영 리스크 | robots.txt, 약관, 차단 가능성, 요청량 제한 |
| 유지보수 비용 | 사이트 구조 변경 빈도, Selenium 필요 여부 |

권장 점수는 1~5점이다. 총점이 높고 운영 리스크가 낮은 대상부터 구현한다.

## 대상 레지스트리 포맷

수집 대상은 YAML 또는 DB 테이블로 관리한다. 초기에는 `docs/crawler-targets.yaml` 같은 파일로 시작하고, 운영 단계에서 DB 테이블로 옮긴다.

```yaml
- provider: HYUNDAI_DEPT
  name: 현대백화점 문화센터
  group: department_store
  base_url: https://www.ehyundai.com
  list_url:
  detail_url_pattern:
  priority: 1
  status: candidate
  login_required: unknown
  selenium_required: unknown
  api_available: unknown
  expected_fields:
    - title
    - branch
    - fee
    - schedule
    - target
    - image
    - description
  risks:
    - terms_check_required
  notes: 전국 백화점 문화센터 후보. 목록/상세 구조 조사 필요.
```

## 상태 값

| 상태 | 의미 |
|---|---|
| candidate | 후보로 등록됨 |
| discovery | URL/API/HTML 구조 조사 중 |
| ready | 크롤러 구현 가능 |
| implementing | 크롤러 구현 중 |
| testing | 제한 건수로 수집 품질 검증 중 |
| active | 정기 수집 중 |
| paused | 점검, 차단, 약관 이슈 등으로 일시 중단 |
| rejected | 수집 대상에서 제외 |

## 후보 조사 절차

1. 사이트의 목록 페이지와 상세 페이지를 찾는다.
2. 로그인 없이 접근 가능한지 확인한다.
3. 개발자 도구 Network 탭에서 검색 API가 있는지 본다.
4. 페이지네이션, 지점 필터, 카테고리 필터 구조를 기록한다.
5. 샘플 20건을 수집해 필드 완성도를 확인한다.
6. robots.txt와 이용약관을 확인한다.
7. 난이도와 우선순위를 등록한다.

## 크롤러 구현 순서

1. 목록 수집
2. 상세 수집
3. 지점/좌표 매핑
4. 제목 정제
5. 대상/연령 정제
6. 일정/요일/시간 정제
7. 이미지 수집
8. 중복/변경 감지
9. stale 처리
10. 품질 리포트 연결

## 품질 리포트 기준

신규 대상은 최소 100건 테스트 후 아래 항목을 확인한다.

| 항목 | 목표 |
|---|---:|
| 제목 | 99% 이상 |
| 지점 | 99% 이상 |
| 원본 URL | 99% 이상 |
| 일정 원문 | 95% 이상 |
| 요일/시간 정규화 | 90% 이상 |
| 대상/연령 | 80% 이상 |
| 수강료 | 95% 이상 |
| 이미지 | 70% 이상 |
| 상세 설명 | 70% 이상 |

정기 수집 대상은 provider별 active 건수, inactive 건수, 누락 필드, 신규/변경/삭제 건수를 리포트로 남긴다.

## stale 처리 원칙

- 크롤러가 실패했거나 0건 수집된 경우 기존 데이터를 inactive 처리하지 않는다.
- 사이트 점검, 네트워크 오류, 캡차, 로그인 만료는 수집 실패로 기록한다.
- 정상 수집이 확인된 경우에만 이전 데이터와 비교해 inactive 처리한다.
- 가능하면 provider 전체가 아니라 지점 또는 카테고리 단위로 stale 처리한다.

## 운영 메모

- 대형 유통사와 공공기관을 먼저 확장한다.
- 민간 클래스 플랫폼은 약관과 제휴 가능성을 먼저 확인한다.
- AI는 제목/대상/태그/요약 보정에 사용하고, 원본 필드는 반드시 보존한다.
- 크롤러별 실패 원인을 리포트에 남겨야 한다. 예: 점검, 네트워크, 구조 변경, 로그인 필요, 캡차.
- 신규 대상 추가 시 100건 테스트, 1000건 테스트, 정기 수집 순서로 승격한다.
